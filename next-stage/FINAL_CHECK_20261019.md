## 실제 수정
- app.mjs: 마우스 누름 상태를 일시정지/재개/홈/재시작에서 초기화. OS 모션 감소 설정을 저장된 효과 ON보다 우선 적용하고 변경도 즉시 반영.
- app.mjs: 메뉴/결과/일시정지에서 게임 RAF 반복 중지. 로딩·플레이·재개에서 단일 루프만 예약. 오디오 시계, 채보, 판정 계산은 동일.
- ui-polish.css: 844×390 가로 화면용 결과/실패 패널 압축.
- index.html: 캐시 버전 갱신, `?perf=1`일 때만 진단 모듈 로드.
- performance-check.mjs: 실제 RAF 간격·입력 콜백→다음 RAF 측정. 최대 3,600개 프레임/200개 입력 표본으로 제한하고 초당 한 번만 표시. 일반 URL에서는 로드하지 않음.
- tests/test_final_ui.mjs: 실제 오디오 브리지의 터치 좌표/취소/입력 차단, 실제 finish 함수의 기록 저장, 프레임 스케줄러 회귀 테스트.

- 설정: 볼륨79%, 속도1.15로 변경한 뒤 새로고침해 유지 확인. 플릭/효과 토글 동작 확인 후 80%,1,ON으로 복원.

- 결과: 실제 연습 결과 점수210, PERFECT1, GREAT0, MISS212, 최대콤보1, 정확도0.5%. 연습 기록 미저장 안내 확인.
- GAME OVER: 일반 모드 무입력 시 MISS18, 점수0, 체력 소진으로 실패 확인. 다시 플레이로 READY 재진입.
- 로딩: 실제 다운로드/디코딩 상태 확인. READY 실제 숫자4 표시 캡처.

- 터치: 실제 브리지 코드의 400×240→800×480 좌표 변환, 캔버스 밖 입력 무시, 취소 및 pause 정리를 자동 검사. 물리 휴대폰 터치 검증은 미수행.

## 성능 수치
Windows 인앱 브라우저, PC 1280×720, 표시 주기 약120Hz. 별도 모바일 기기 벤치마크가 아니다.

| 구간 | 표본 | 평균 FPS | 평균 간격 | p95 간격 | 33.34ms 초과 |
|---|---:|---:|---:|---:|---:|
| 메뉴 안정 구간 | 3600 | 115.8 | 8.64ms | 9.30ms | 1 |
| 실제 플레이 PC 구간 | 3600 | 118.8 | 8.41ms | 8.60ms | 2 |
| 최종 코드 가로 844×390 플레이 | 636 | 118.9 | 8.41ms | 8.60ms | 1 |

PC 플레이 입력→다음 RAF p95 29.30ms, 단 4개 표본. 자동화 입력 전달·화면 캡처의 영향이 있으며 하드웨어 입력→화면 표시/스피커까지의 종단 지연이 아니다. 초기 WebGL/디코딩 구간에는 지연 표본이 발생했다. 측정값은 RAF callback 간격이며 GPU 완료 시간을 측정하지 않는다. 메뉴 루프 제거는 이 측정 후 적용했고 회귀 테스트로 중지/재개를 검증했다.
