# UI 마감 검토

## 수정 범위
`ui-polish.css`를 최종 스타일 계층으로 추가하고 `index.html`에 연결했다. 내비게이션/검색 아이콘을 자체 SVG로 교체했다. `tests/postplay-preview.html`에도 같은 스타일을 연결했다. app/core/audio/renderer 및 기존 사이트/유리 버전은 수정하지 않았다.

## 세 차례 캡처 → 비교 → 수정
1. 1280×720: 상세 패널이 길어 시작 버튼이 아래로 밀리고 선택 링/점무늬가 강했다. 앨범 영역과 여백을 압축하고 카드 글씨를 확대, 선택 링과 패턴을 정리했다. `../polish-1-before.png`, `../polish-1-after.png`.
2. 844×390: 곡 목록이 화면 하단에서 시작하고 상세 버튼까지 접근이 길었다. 짧은 가로 화면에서 제목/상단 여백을 줄이고 상세 패널 및 사이드바를 스크롤 가능하게 했다. `../polish-2-before.png`, `../polish-2-after.png`.
3. 844×390 설정 모달: 하단 여백과 닫기 버튼 크기, 문자 아이콘 정렬을 점검했다. 짧은 높이용 모달 여백/44px 닫기 버튼, 선 두께가 일정한 SVG와 사이드바 가로 넘침 수정을 적용했다. `../polish-3-before.png`, `../polish-3-after.png`.

실제 비교 레퍼런스: https://yashihei.hatenablog.com/entry/2023/12/30/181813 의 곡 선택 스크린샷. 얇은 선택 프레임, 재킷 중심 배치, 구분되는 난이도 강조를 참고했고 원본 리소스는 복사하지 않았다.

## 애니메이션/성능
- 공통 120/200/280ms와 동일한 easing 사용. 버튼/카드 transform, 화면 opacity, 결과 패널 8px 등장 효과.
- 기존 모달 퇴장 및 게임 시계는 유지. 새 화면 전환이 입력이나 오디오 시작을 기다리게 하지 않는다.
- 모달과 카운트다운의 backdrop blur 제거. 정적인 패널 그림자와 이중 하이라이트 사용. 매 프레임 JS 작업 추가 없음.
- OS reduced-motion 및 기존 시각 효과 OFF 지원. 브라우저에서 OFF 시 animationName=none, backdropFilter=none 확인 후 원래 ON으로 복원.

## 검증
- 1920×1080 PC 및 1024×768 태블릿 DOM 가로 넘침 없음, 캡처 확인. 1280×720 노트북, 844×390 가로 화면을 반복 검토.
- 곡 변경 시 제목/BPM 갱신, MASTER 선택, 다음 페이지 이동, 설정 ESC 닫기 확인.
- 나다움 HARD 연습 모드에서 실제 재생, ESC 일시정지, 계속하기 후 00:20→00:22 진행, 곡 선택 복귀 확인. 브라우저 오류 로그 없음. `../polish-pause.png`.
- tests/test_web_next.mjs: 34,985 판정 비교와 180채보/30곡 통과.
- test_keyboard_bridge, test_settings_motion, test_transitions_ui, test_play_hud 통과.
- 결과/AP 및 로딩 추가 캡처는 명시적인 격리 UI fixture 사용. 실제 AP 달성으로 해석하면 안 된다.
- 실제 터치 하드웨어와 프레임 시간 벤치마크는 미수행. 작은 화면은 세로 스크롤을 허용한다. 온라인 배포는 수행하지 않았다.
