# 플레이 전후 UI 검증 (2026-10-18)

## 범위
- `postplay.css`: 결과/실패 패널, FC/AP 타이틀, 로딩, READY 표시만 스타일링.
- `transitions-ui.mjs`: 실제 오디오 준비 상태를 표시하고 값이 바뀔 때만 DOM 갱신. 카운트다운 숫자 변경 시 짧은 불투명도 애니메이션.
- `app.mjs`, `index.html`: 위 프레젠테이션 연결, 곡/난이도 표시, 실패 안내 문구.
- 기존 점수/정확도/판정 통계와 기록 저장 코드, 카운트다운 및 오디오 시작 예약 계산 유지. 원본 사이트와 glass-stage 수정 없음. 이번 작업은 로컬 구현이며 배포하지 않음.

## 레퍼런스
https://note.com/5gkyu/n/n1edbb0c9617f 의 실제 결과 스크린샷을 확인했다. 보라색 보조 영역, 밝은 통계 패널, 강조된 점수와 큰 등급을 독립적인 CSS로 재구성했다. 원본 이미지 리소스는 사용하지 않았다.

## 검증
- `node tests/test_web_next.mjs`: 34,985 판정 비교, 180 채보 / 30곡 통과.
- `node tests/test_transitions_ui.mjs`: 실제 상태별 진행 표시, 오류 유지, FC/AP/실패 우선순위, 카운트다운 표시 통과.
- `node tests/test_play_hud.mjs`, `node tests/test_settings_motion.mjs` 통과.
- `node --check web-next/app.mjs` 통과.
- 브라우저에서 나다움 HARD 1절 실제 다운로드/디코딩, READY, 무입력 실패(점수 0 / MISS 18 / 정확도 0%), 다시 시작, 곡 선택 복귀 확인.
- 일반 클리어/FC/AP는 격리된 `tests/postplay-preview.html`의 명시적 테스트 데이터로 시각 검증했다. 실제 FC/AP 달성 플레이를 완료한 것은 아니다. 테스트 페이지는 앱/음악/기록 저장을 실행하지 않는다.
- 390px 모바일 폭에서 긴 제목 및 결과 패널 가로 넘침 없음. 1280×720에서 하단 버튼이 밀리던 문제를 낮은 화면용 여백 조정으로 수정.

## 성능 및 한계
CSS 그라데이션/짧은 애니메이션을 사용하며 별도 매 프레임 픽셀 처리는 없다. 로딩은 상태/진행률이 바뀔 때만, 카운트다운은 숫자가 바뀔 때만 갱신한다. 감소된 모션 설정을 지원한다. 기기별 FPS 측정과 전체 곡 실제 재생은 이번 검증에 포함하지 않았다.
