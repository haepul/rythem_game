# 트랙·배경 개선 v3 (2026-10-13)

## 기존 구조와 좌표
main.py의 TRACK_TOP_Y=110, TRACK_BOTTOM_Y=JUDGE_Y=410, TRACK_TOP_W=286, TRACK_BOTTOM_W=724, 800×480 좌표계를 유지했다. get_perspective_pos의 progress ** 1.55, 4레인 투영과 입력 변환을 유지했다.
이전 stage_renderer는 투명한 단색 트랙/패널을 합성했고, main 루프는 비트 그리드와 입력 레인 전체 다각형, 맥동 판정선 및 키 패드를 추가로 그렸다. 판정선 뒤에 그린 패드가 흰 중심선을 가리는 문제가 있었다.

## 변경 구조
- generate_bg_surface → background_texture: 남색·보라·검정 기반에 기존 곡별 colors/accent를 혼합한다. 100×60 조명장을 한 번 계산해 부드럽게 확대하고 별빛/작은 도형을 배치한다. 낙하 방향을 방해하지 않도록 배경은 정적으로 유지한다.
- composed_stage: 바닥 그림자/앞면, 어두운 원거리 → 은은하게 밝은 근거리 트랙, 교대 레인 색상, 원근에 따라 폭이 달라지는 네온 경계와 낮은 알파의 내부 구분선을 최종 RGB 화면으로 합성·캐싱한다.
- draw_track_feedback: 기존 비트 시각을 같은 투영 함수로 그린다. 가까워질수록 알파가 증가하며, 중심 레인선보다 과하게 밝아지지 않는다.
- pressed_glow_surface는 동적 그리드 작업용 Surface로 재사용한다. 입력 레인 효과는 input_lane_texture의 사전 렌더링된 아래쪽 그라데이션을 필요한 영역만 blit한다.
- judge_texture: 정확히 Y=410에 흰색 1px 코어, 얇은 색상층과 약한 발광. 코어는 일정하고 외부 발광만 최대 약 12% 변화한다. 기존 키 패드를 제거하여 기준선을 가리지 않으며 키 라벨은 선 아래에 남긴다.

## 성능 및 설정
정적 배경 캐시 8개, 최종 무대 4개, 입력 텍스처 24개, 판정선 스트립 32개로 상한을 둔다. 입력 효과는 전체 화면 텍스처 대신 경계 영역만 저장/합성한다.
STAGE_EFFECTS=False: 배경/그림자/네온 발광 비활성화(소스 상수 변경 후 재시작). INPUT_EFFECTS=False: 입력 조명 비활성화. BEAT_GRID=False: 비트 그리드 비활성화. 기본 레인과 흰 판정선은 유지된다.
PC SDL dummy, 600프레임, 두 레인 입력, 트랙/배경/피드백만 측정: 최초 11.993ms, 캐시 후 중앙값 0.518ms, p95 0.760ms. 전체 게임/브라우저/휴대전화 FPS 수치가 아니다. 최초 합성 비용과 캐시 메모리 사용은 증가하지만, 무거운 픽셀 작업은 매 프레임 반복하지 않는다.

## 검증
- 관련 회귀 테스트 98개 통과. 새 검사는 투영 앵커/레인 경계, 모든 맥동 단계의 판정선 코어, 입력 시 이웃 레인 불변, 세 곡 테마의 깊이/노트 대비, 캐시 후 Surface 생성 없음, 그리드 깊이별 알파, 효과 OFF 동작을 포함한다.
- 대표 테마/원근 위치에서 노트 중심 RGB 합이 트랙의 4배 이상인지 검사했다. 이는 WCAG 명암비나 모든 노트 픽셀의 보장은 아니다.
- 네 종류·63ms 연타·겹침·원거리·진행 리본의 이미지 생성 후 시각 확인.
- get_perspective_pos AST 및 판정 모듈 세 개의 SHA256 불변. 노트 렌더러와 음악 시각·BPM·점수 계산을 변경하지 않았다.
- PyGBag 0.9.3 / Python 3.12 빌드 성공. 배포 패키지 내부 소스 일치 확인.
- 실제 휴대전화 성능과 터치 실기 테스트는 수행하지 않았다.

배포 대상은 /glass-stage/만이며, 기존 루트와 /glass/ 파일을 보존한다.
